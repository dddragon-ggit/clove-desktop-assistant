## 接力原则

- `docs/desktop-assistant-spec.md` 是活文档，不是铁律；实现中发现更合理的产品方向时，可以同步微调。
- 项目变化要记录到 `工作进度.md`，后续按每日追加，不要大面积改旧记录。
- 单个 `desktop_assistant/` 下的 Python 文件一般不要超过 400 行；如果接近上限，先拆模块。
- UI 目标不是工程调试面板，而是一个“每天愿意打开”的桌面管理助手。
- 用户重视美感、短路径、自然反馈和稳定体验；不要让普通用户直接面对内部协议、traceback 或过多配置项。
- 不要把 API Key 或其他敏感信息写入文档、测试或提交内容。

## Real Provider 配置交接

不要把完整 API Key 写入 `docs/`、测试、日志或提交内容。当前项目已经支持从本地配置读取密钥，交接时应交接“配置位置与验证方式”，而不是复制密钥本体。

下个会话做 real 模式测试时不需要手动知道明文 key：代码会从同一工作区的 `runtime/data/model_provider.json` 自动读取。只要这个文件还在，直接运行 real 模式命令即可调用大模型。接力者不要把 key 打印出来，也不要把 key 复制进新的文档。

默认配置路径：

```text
runtime/data/model_provider.json
```

当前本机配置摘要：

```json
{
  "provider_name": "OpenAI",
  "base_url": "https://www.fhl.mom",
  "wire_api": "responses",
  "model": "gpt-5.4",
  "review_model": "gpt-5.4",
  "model_reasoning_effort": "xhigh",
  "disable_response_storage": true,
  "requires_openai_auth": true,
  "api_key_storage": "plaintext api_key",
  "api_key_masked": "sk-2...6e4a"
}
```

加载优先级：

1. 环境变量优先：`DESKTOP_ASSISTANT_API_KEY`、`DESKTOP_ASSISTANT_BASE_URL`、`DESKTOP_ASSISTANT_MODEL`、`DESKTOP_ASSISTANT_REVIEW_MODEL` 等。
2. 如果环境变量不完整，则读取 `runtime/data/model_provider.json`。
3. `model_provider.json` 支持明文 `api_key`，也兼容旧版 `api_key_encrypted`。

## 当前产品形态

应用默认启动为新版 Shell：

- 右上角小型方框助手。
- 可最小化为橙色绒毛小球。
- 小球可拖动、会眨眼、眼睛跟随鼠标。
- 方框可拖动、可缩放，背景已改为不透明主体，仅圆角外侧透明。
- 首页显示问候语、重要待办数量、最近待办状态色。
- 首页底部输入框支持预测提示，用户可用 Tab 接受。

当前主入口：

- 待办任务清单。
- 工作环境选择。
- 继续刚才的工作。
- 输入任意内容进入路由：待办、工作区、继续工作或普通对话/规划。

## 已具备的后端能力

核心编排：

- `WorkflowOrchestrator`：规划、策略、审查、执行、失败恢复。
- fake / real 双后端。
- real planner/reviewer 已有结构化 schema、重试、fallback、应用清单辅助匹配。
- 失败自动修正已有基础：能记录失败、限制重复失败、部分场景可重新规划或停止。

能力目录与执行：

- `capability/` 维护动作能力、风险、handler 状态。
- `WindowsExecutor` 支持打开应用、聚焦应用、列窗口、窗口操作、打开 URL、文件、文件夹、项目、查询信息、待办等。
- `open_app` 已接入 `app_inventory.json`。
- 应用清单启动时缓存，避免每次扫描。
- 有简易应用名索引，模型匹配时可带应用名列表，提高容错。

待办：

- `todo/` 是真实 To-do 后端，不再是 mock。
- 支持标题、描述、重要性、优先级、截止/提醒时间、完成、推迟、取消、删除。
- 支持任务是否需要电脑完成。
- 支持将任务绑定到工作区动作。
- 支持执行记录回写。
- 首页状态色规则已实现：30 分钟内偏红，3 小时内偏橙，普通偏黄，完成偏绿。

工作区：

- `workspace/` 可从用户目标、待办、当前活动生成工作区建议。
- 工作区建议可编辑、勾选、添加、删除动作。
- 应用目标用 `app_inventory.json` 下拉/补全。
- 文件/文件夹目标用系统选择器。
- 可保存为 `WorkflowRecipe`，后续加载复用。
- 通用工作区和待办工作区都走动作级确认。

确认与白名单：

- `confirmation/` 已实现动作级确认流。
- 支持拒绝、本次执行、永久确认。
- 永久确认写入 action-level trust。
- 低风险动作默认不强行进入白名单。

活动与预测：

- `activity/` 非侵入式采集前台应用、窗口标题、可能文件、项目元数据。
- 不监听键盘，不截图，不 OCR，不读剪贴板，不读文件正文，不读网页或聊天内容。
- `habits/` 维护每日行为记录、14 天清理、下一步行为预测。
- 预测优先级：紧急待办、未完成工作区、恢复中断、习惯时间、上下文补全、待办兜底。

信息查询：

- `answer_query` 已能联网查询并返回摘要、来源、可信度和兜底搜索。
- 查询 metadata 会记录尝试来源、来源数量、置信度说明、降级原因和检查时间。
- 天气查询优先使用结构化天气接口；搜索直接答案和网页摘要作为后续降级。

UI 状态：

- `ui_state/` 持久化方框/小球位置、大小、模式、隐身、透明度等。

## 当前已知风险

- Shell UI 是高风险区域。小球、方框、透明背景、拖动、缩放、页面切换互相影响，改动后一定跑 UI 相关测试。
- 小球当前采用“透明背景状态音波”方向，不再绘制橙色实体球壳；如果用户想回到绒毛双眼版本，可参考 `shell_orb_furry_backup.py`。
- `shell_pages.py` 已拆到约 100 行；继续加页面时仍优先拆出独立 page builder、view 或 flow 文件，避免重新接近 400 行。
- `工作进度.md` 在 PowerShell 里常显示乱码，但实际内容多为 UTF-8；不要因为终端显示误删。
- real provider 虽有本地单测和 smoke 工具，但真实多轮质量评测仍需要继续扩展。
- 信息查询已补来源、置信度、验证状态、来源概况和多来源摘要置信度提升；后续仍可接更专业的财经/天气数据源。
- 配方系统已有保存/加载、首页命中已保存 workspace recipe 直达确认；后续可继续做更强的方案版本管理和一键执行入口。
- UI 视觉语言还没有完全统一，尤其是待办详情、工作区确认、执行反馈页面可以继续打磨。

## 建议下一步

优先级从高到低：

1. 继续补真实执行验收  
   用 real 模式走打开应用、打开网页、信息查询、窗口列表等少量真实路径，确认速度、失败反馈和权限弹窗体验。

2. 信息查询专业数据源  
   在现有多来源摘要基础上，为天气、财经价格等高频查询接更稳定的数据源和来源展示。

3. 窗口/应用状态管理增强  
   现在窗口动作已有后状态确认；后续可做窗口整理、等待再聚焦、最近工作恢复和常用项目推荐。

4. 配方系统继续产品化
